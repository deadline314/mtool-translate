# [MT-5] 支援 Unity 遊戲翻譯

> 狀態：待辦

## 內文

### 需求
MTool 只能開一部分 Unity 遊戲，開不了的那些（特別是 IL2CPP 版本）沒辦法用 MTool 的翻譯檔流程。這些遊戲常見的作法是 BepInEx 加 XUnity.AutoTranslator，翻譯器要能為這類遊戲產出可用的翻譯，並沿用 MT-3 的術語表與上下文機制。

可能的兩種接法（開工前與使用者確認要做哪一種或兩種都做）：

- 讀取 XUnity 收集到的原文檔，輸出它能讀取的翻譯檔（離線）
- 讓翻譯器充當 XUnity 的自訂翻譯服務，遊戲邊玩邊翻（即時）

### 來源
使用者，2026-10-19 對話：「那有辦法支援 unity嗎?」；之後決定「先做 mtool 的版本」，Unity 延後。

### 驗收條件
- [ ] 確認要支援離線翻譯檔、即時翻譯服務，或兩者都要
- [ ] 能讀取 XUnity 收集的原文檔，輸出的翻譯檔放回遊戲後，遊戲畫面顯示譯文
- [ ] 含 `=`、換行的句子經過翻譯後，XUnity 仍能正確讀取（不錯行、不截斷）
- [ ] Unity 富文字標籤（例如 `<color=...>`、`<b>`）翻譯後完整保留
- [ ] 術語表與前文參考在 Unity 流程中同樣生效
- [ ] 進度條在 Unity 流程中同樣正確完整（同 MT-4 的標準）
- [ ] 至少用一款 Mono 版與一款 IL2CPP 版的 Unity 遊戲實機驗證並附截圖

### 測試流程
1. 在 Unity 遊戲安裝 BepInEx 與 XUnity.AutoTranslator，玩一段讓它收集原文
2. 用翻譯器選擇收集到的原文檔並翻譯
3. 把輸出的翻譯檔放回遊戲，重新啟動遊戲
4. 預期：對話、選單顯示譯文，控制碼與富文字樣式正常
