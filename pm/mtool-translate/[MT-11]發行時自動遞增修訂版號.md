# [MT-11] 發行時自動遞增修訂版號

> 狀態：完成

## 內文

### 需求
每次發行都要自己想好、打上下一個版本號（例如 `make release VERSION=1.0.1`）。希望不加版本號直接 `make release` 時，自動發行下一個修訂版（1.0.0 → 1.0.1）。

- 目前版本已經發行過時，自動把修訂版號 +1
- 發行到一半失敗、版本號已改好但還沒推上去時，重跑要接著發行同一個版本，不能跳號
- 仍可以指定版本，但不能比目前的版本舊

### 來源
使用者，2026-10-19 對話：「能不能設置成 make release 如果沒加VERSION就預設最小版號+1? 例如 1.0.0 -> 1.0.1」

### 驗收條件
- [x] 目前版本已發行過時，`make release` 自動發行修訂版號 +1 的版本（1.0.0 → 1.0.1、1.2.9 → 1.2.10），並在畫面上說明
- [x] 目前版本還沒發行過時，`make release` 直接發行目前版本
- [x] 打包失敗後不加版本號重跑，接著發行同一個版本，不會重複 commit、不會跳號
- [x] `make release VERSION=x.y.z` 照常可用；指定的版本比目前舊時擋下並說明
- [x] 版本已發行過時的錯誤訊息直接建議下一個可用的版本號
- [x] 演練 `make release-dry` 不加版本號時，顯示會自動發行哪個版本，不改動任何東西
- [x] 說明文件與指令說明都已更新

### 測試流程
1. 在已發行 v1.0.0 的狀態執行 `make release-dry`，預期顯示「版本 1.0.0 已經發行過，這次自動發行 1.0.1」，且沒有改動任何檔案
2. 執行 `make release`，預期發行 v1.0.1
3. 執行 `make release VERSION=0.9.0`，預期被擋下並說明版本比目前舊

原本每次發行都要自己指定下一個版本號。
現在直接執行 `make release`：目前版本已經發行過，就自動把修訂版號 +1 再發行，並在畫面上說明這次發行哪個版本；目前版本還沒發行過（例如上次打包失敗、版本號改好了但沒推上去），就接著發行目前版本，不會跳號。指定版本照常可用，但不能比目前舊；版本已發行過時，錯誤訊息會直接建議下一個可用的版本號。
用模擬整個發行流程的測試確認：自動遞增、未發行時沿用、打包失敗後重跑不重複 commit 也不跳號、指定版本不能倒退。也對真實的 repo 演練：v1.0.0 已發行時不加版本號，顯示會自動發行 1.0.1，且沒有改動任何檔案或 tag；指定 0.9.0 時被擋下。
