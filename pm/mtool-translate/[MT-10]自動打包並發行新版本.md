# [MT-10] 自動打包並發行新版本

> 狀態：完成

## 內文

### 需求
每次要給別人新版本，都得自己打包、壓縮、上傳，而且其他人無從得知哪一份是最新版。希望發行新版本變成一個步驟：

- 推上新版本號的 tag 時，GitHub Actions 自動打包並放到 GitHub Release，其他人從 Release 下載
- 在本機也能用一個指令（make release）完成同樣的發行，GitHub Actions 不能用時照樣能發行
- 兩邊都發行時不能互相衝突，打出來的東西要一樣
- 發行前要擋下會出錯的狀況：版本號重複、有未 commit 的修改、不在 main、落後遠端
- 每次推到 main 或開 PR 時自動跑全部檢查

### 來源
使用者，2026-10-19 對話：同意開「用 GitHub Actions 自動打包發行版」的工作，並補充「然後本機也能 make release。這樣在 github action 不能用的時候也能正常」。

### 驗收條件
- [x] 版本號只有一個來源，視窗標題、自我檢查報告、發行檔名都顯示同一個版本
- [x] 本機 `make release VERSION=x.y.z` 一個指令完成：改版本號並 commit → 全部檢查 → 打包 → 打包後自我檢查 → 推 commit 與 tag → 上傳 zip 到 GitHub Release
- [x] 沒有 make 時，用同一支 Python 腳本執行效果相同
- [x] 發行前會擋下：不在 main、有未 commit 的修改、落後遠端、版本號格式錯誤、版本已發行過，並說明原因
- [x] 打包失敗時版本號的 commit 不會推上去；修正後用同一個版本號重跑，不會重複 commit
- [x] 本機沒有 gh 或沒登入時，仍會推 tag，交給 GitHub Actions 上傳，並提示之後可以補傳
- [x] 可以先演練發行：只做檢查與打包，不 commit、不打 tag、不上傳
- [x] 發行檔名使用英文並帶版本號，Release 已存在時覆蓋同名附件，本機與 GitHub Actions 誰先完成都不衝突
- [x] 推到 main 時 GitHub Actions 在 Windows 上跑全部自動化檢查並通過
- [x] 在 GitHub Actions 手動執行 Release，打包成功並產出可下載的 zip（不發行）
- [x] 本機演練發行通過
- [x] 實際發行第一個版本：Release 頁面有 zip，下載解壓後可以開啟

### 測試流程
1. 在專案資料夾執行 `make release-dry VERSION=1.0.0`，預期檢查與打包都通過，最後列出正式執行時會做的事
2. 推一個 commit 到 main，到 GitHub 的 Actions 頁面，預期 CI 通過
3. 在 Actions 頁面手動執行 Release，預期打包成功、Artifact 有 zip
4. 執行 `make release VERSION=1.0.0`，預期推上 tag `v1.0.0`，Release 頁面出現 `MToolTranslator-v1.0.0-windows.zip`
5. 從 Release 下載 zip、解壓、開啟 exe，預期視窗標題顯示 1.0.0
6. 再執行一次 `make release VERSION=1.0.0`，預期被擋下並提示版本已發行過

# Commit-1

## 內文

原本每次發行都要自己打包、壓縮、上傳，也沒有固定的版本號。
現在版本號集中在一處，視窗標題、自我檢查報告、發行檔名都會顯示。本機執行 `make release VERSION=x.y.z`（沒有 make 時用同一支 Python 腳本）就會依序：檢查 git 狀態 → 改版本號並 commit → 跑全部檢查 → 打包並自我檢查 → 推 commit 與 tag → 上傳 zip 到 GitHub Release。推 tag 也會觸發 GitHub Actions 走同一套步驟；兩邊誰先完成都可以，Release 已存在時就覆蓋同名附件，所以 GitHub Actions 不能用時，本機照樣能完整發行。本機沒有 gh 時改由 GitHub Actions 上傳。另外每次推到 main 或開 PR，都會在 Windows 上自動跑全部檢查。
發行前的防呆（不在 main、有未 commit 的修改、落後遠端、版本號格式錯、版本已發行過）、打包失敗時不推送、重跑不重複 commit、沒有 gh 時只推 tag、演練不改任何東西，都用模擬整個發行流程的測試確認。實際在 GitHub 上跑過 CI 與手動 Release，本機也跑過完整演練。

### 測試結果

| 項目 | 結果 |
|---|---|
| 自動化檢查（本機） | 通過 88 / 88 |
| GitHub Actions CI（windows-latest） | 通過 88 / 88 |
| GitHub Actions 手動執行 Release | 打包與自我檢查通過，產出 zip 21.5 MB，略過發行步驟 |
| 本機演練 `make release-dry VERSION=1.0.0` | 檢查、打包、自我檢查 17 項全部通過，zip 20.3 MB，未改動任何東西 |
| 有未 commit 修改時執行 `make release` | 正確擋下並說明原因 |
